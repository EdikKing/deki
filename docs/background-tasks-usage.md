# Deki 后台任务使用指南

本文介绍如何把 Deki 请求放到后台运行，如何在 Task Center 中处理审批、暂停、恢复、重试和结果，以及当前版本在应用退出和任务恢复方面的边界。

底层 Task、Run、事件模型和长期路线见[多 Agent、后台任务与 Plan 模式完整规划](./multi-agent-background-tasks-plan-mode.md)。

## 什么是后台任务

后台任务是一个拥有独立 Task ID、Run、Session 上下文和生命周期的 Agent 请求。提交后，你可以切换会话或项目，任务仍由当前 Deki 主进程继续调度。

后台任务适合：

- 阅读较多文件并生成分析报告。
- 执行需要较长时间的代码调查。
- 运行测试、Lint 或类型检查。
- 在一个任务运行时继续处理另一个会话。
- 同时排队多个互不依赖的工作。
- 在后台生成 Plan，稍后集中审阅。
- 让包含多个 Worker 的调查不占用当前聊天界面。

后台任务不等于：

- 系统定时任务。
- Deki 完全退出后仍运行的 daemon。
- 无需审批的自动执行。
- 与当前会话共享同一个流式输出区域。
- 可以安全重复所有副作用操作的队列。

## 当前实现状态

当前版本支持：

- 直接把新 Prompt 作为后台任务提交。
- 将正在运行的前台任务转到后台。
- 在 Task Center 搜索和按项目、状态筛选任务。
- 查看任务目标、Run、事件、结果、Artifact、Plan 和 Worker。
- 单独暂停、恢复、取消和重试任务。
- 在 Task Center 处理 Tool 审批和 Agent 提问。
- 任务完成、失败、等待审批时发送系统通知。
- 应用重启后识别此前未结束的任务为 `interrupted`。

当前不支持：

- 用户明确退出 Deki 后继续执行。
- 进程崩溃后从任意 Tool 调用中间位置无条件自动续跑。
- 自动重放结果未知的外部副作用。
- 定时、Git、Issue 或文件变化触发器。
- 独立本地 daemon 或远程 Runner。

## 前台与后台的区别

| 项目 | 前台任务 | 后台任务 |
| --- | --- | --- |
| 提交入口 | 主发送按钮或 Enter | “后台运行”按钮 |
| Session | 当前会话，必要时创建 Task | 从当前上下文创建独立会话分叉 |
| 流式输出 | 当前聊天直接显示 | 主要在 Task Center 查看 |
| 切换项目/会话 | 运行期间通常占用当前会话 | 可以继续浏览其他内容 |
| 审批 | 当前会话和 Timeline | Task Center 中只阻塞对应任务 |
| 完成结果 | 当前聊天 | Task Center，可打开关联会话 |

两种交付方式都通过相同的 Permission Engine、Tool Gateway、Git Checkpoint 和审计系统。

## 使用前准备

1. 配置可用模型。
2. 如果任务需要项目工具，打开并信任正确的项目。
3. 检查当前权限模式。
4. 确认 Git Checkpoint 是否启用。
5. 对长任务写清楚成功条件和验证方式。
6. 在“设置 → Agent”中检查最大并发任务数。

`maxConcurrentRuns` 默认为 1，可配置范围为 1～8。默认设置下，第二个后台任务通常会进入“排队中”，等前一个任务释放执行槽后再启动。

## 方法一：直接提交到后台

### 操作步骤

1. 在消息输入框写入完整任务目标。
2. 保持“执行”模式；如果只想生成计划，则选择“规划”模式。
3. 点击输入框右侧的“后台运行”按钮，图标为 `↗`。
4. 界面出现“已提交到后台”提示。
5. 点击提示，或打开 Task Center 查看任务。

普通会话命令不能在后台运行。例如 `/remember`、`/model` 和 `/doctor` 必须以前台方式提交。

### 推荐 Prompt 结构

```text
目标：

范围：
- 可以读取或修改：
- 不要修改：

完成标准：
- （填写）
- （填写）

验证：
- （填写）

如果需要扩大范围、安装依赖、执行 Git 写操作或访问工作区外路径，请先请求审批。
```

写清范围可以减少后台任务在你不关注当前界面时反复等待输入。

## 方法二：把运行中的任务转到后台

当一个前台任务已经开始运行时，Composer 会显示“转到后台”按钮，图标为 `⇱`。

点击后：

1. 当前 Task 保持原 ID 和运行状态。
2. 聊天界面解除忙碌状态。
3. 任务继续由后台 Scheduler 管理。
4. 后续输出、审批和完成状态从 Task Center 查看。

适用情况：

- 调查时间比预期长。
- Agent 开始运行测试或读取大量文件。
- 你希望立即切换到其他项目。
- 当前任务派发了 Worker，需要等待并行结果。

转到后台不是复制任务，也不会从头重新执行。

## 示例一：后台完成代码检查

```text
请后台检查这个项目的配置加载流程。

范围：
- packages/config
- packages/settings
- desktop main process 中的初始化代码

目标：
- 找出配置损坏、并发更新和 Secret 泄漏方面的风险；
- 不修改文件；
- 每个结论引用文件和行号；
- 输出按严重程度排序的报告；
- 最后列出建议补充的单元测试。
```

提交后，你可以切换到其他会话。任务完成时，从 Task Center 打开 Run Summary 和 Artifact。

## 示例二：后台修改并验证

```text
修复 CLI 帮助文档中的命令示例，并完成验证。

约束：
- 只修改 README.md 和 docs/cli.md；
- 不更新依赖；
- 不执行 git commit 或 push；
- 修改前保留 Git Checkpoint；
- 完成后运行 pnpm lint 和相关测试；
- 如果实际 CLI 语法与文档冲突，以代码和真实命令输出为准；
- 返回修改摘要、验证结果和剩余风险。
```

该任务可能在写入、Shell 或 Git 边界上请求审批。你可以在 Task Center 的“需要处理”分组中批准或拒绝。

## 示例三：后台生成计划

1. 将 Composer 切换到“规划”。
2. 输入：

```text
分析如何把 MCP Server 健康检查改为可观测的状态机。

计划必须包含：
- 当前实现和调用链；
- 数据结构与迁移；
- 主进程和 Renderer 变更；
- 失败恢复；
- 测试与发布验证；
- 明确的非目标。

只生成计划，批准前不要修改代码。
```

3. 点击“后台运行”。
4. 规划 Task 在后台读取项目并生成 Plan。
5. 完成后打开 Plan 面板审阅、要求修改或批准执行。

详见 [Plan 模式使用指南](./plan-mode-usage.md)。

## Task Center

Task Center 是后台任务的统一管理入口。

### 列表和筛选

可以使用：

- 任务、结果或错误全文搜索。
- 项目筛选。
- 状态筛选。
- “运行中”“需要处理”“排队中”“已完成”“失败与中断”等分组。

任务行会显示：

- 标题和项目。
- 当前状态。
- 任务种类：前台、后台、规划、计划执行或 Worker。
- Plan revision 和步骤进度。
- Worker 完成数量。
- 最新结果或错误。
- 最后更新时间。

### 任务详情

选择任务后可以查看：

- 原始目标。
- Agent Tree 和 Worker 状态。
- Worker 数量、Token 和 Tool 预算。
- Plan 当前步骤。
- 待处理审批或用户问题。
- 每次 Run 的 attempt、状态、耗时、错误和结果摘要。
- Diff、测试结果、报告等 Artifact。
- 最近 Task Event。

可以从详情页打开关联会话或 Plan。

## 任务状态

| 状态 | 用户应该做什么 |
| --- | --- |
| `queued` / 排队中 | 等待执行槽；也可以暂停或取消 |
| `running` / 运行中 | 正在执行，可以暂停、转到其他页面或取消 |
| `waiting_approval` / 等待审批 | 检查 Tool、参数、Diff 和风险后批准或拒绝 |
| `waiting_user` / 等待输入 | 回答 Agent 提出的问题 |
| `waiting_workers` / 等待 Worker | 主 Agent 正等待子 Agent，可查看 Agent Tree |
| `paused` / 已暂停 | 根据当前上下文选择恢复或取消 |
| `succeeded` / 已完成 | 查看结果、Artifact、Diff 和验证 |
| `failed` / 失败 | 查看错误，修正外部条件后重试 |
| `cancelled` / 已取消 | 终态；需要时创建新任务 |
| `interrupted` / 已中断 | 检查工作区和副作用状态后恢复 |

## 审批和用户输入

后台任务请求审批时，只会暂停该任务，其他任务仍可运行。

Task Center 会显示：

- 权限类别。
- Tool 和输入参数。
- 操作说明。
- 可用时显示执行前 Diff。

审批选择：

| 选择 | 作用范围 |
| --- | --- |
| 拒绝 | 拒绝本次操作 |
| 允许一次 | 只允许当前具体调用 |
| 当前会话允许 | 当前任务 Session 内允许同类操作 |
| 当前项目允许 | 写入项目本机策略，后续同类操作可复用 |

允许范围越大，使用前越应确认 Tool 分类和项目边界。审批超时等同拒绝。

如果 Agent 请求补充信息，可以选择给定选项或输入自由文本。提交后任务会从 `waiting_user` 回到运行状态。

## 暂停、恢复、重试和取消

### 暂停

暂停用于暂时停止任务并保留可恢复状态。适合：

- 需要先检查当前修改。
- 暂时不希望继续消耗模型 Token。
- 等待外部条件。
- Plan 执行偏离预期，需要 Replan。

暂停不是瞬间冻结进程内任意指令。Deki 会向当前 Agent 发出取消信号并保存任务上下文；正在执行的外部操作能否立即停止取决于 Tool。

### 恢复

恢复会创建新的 Run attempt，并基于持久化 Session、任务目标和已有 Worker Result 继续。

恢复前应检查：

- 工作区仍然存在。
- 项目仍然受信任。
- 之前的写入是否已经发生。
- 外部副作用的结果是否明确。
- 模型和 MCP Server 是否仍可用。

Deki 不会盲目自动重放已经完成或结果未知的副作用操作。

### 重试

重试适用于 `failed` 任务。先修复失败原因，例如：

- API Key 或网络恢复。
- MCP Server 可以启动。
- 测试依赖已准备好。
- 工作区路径重新可用。
- 权限设置允许必要操作。

重试会增加 Run attempt，不会覆盖旧 Run 和错误记录。

### 取消

取消是终止操作：

- 当前 Agent 会收到取消信号。
- 根任务的 Worker 会一并取消。
- 任务进入 `cancelled`。
- 不能直接从 cancelled 状态恢复；如需继续，应创建新任务。

取消不会自动撤销已经发生的文件修改或外部副作用。文件修改可以使用 Diff 和 Git Checkpoint 检查或恢复。

## 应用关闭和崩溃语义

当前版本没有独立 daemon：

- 关闭窗口但应用设置为保持后台运行：Electron 主进程仍在，任务继续。
- 明确退出 Deki：Runtime 停止，运行中任务标记为 `interrupted`。
- 进程崩溃：下次启动会把未正常结束的 Run 识别为 `interrupted`。
- 再次启动后：用户从 Task Center 决定恢复或取消。

因此，不要把当前后台任务当成服务器作业。如果任务必须跨应用退出持续执行，应使用外部 CI、任务队列或等待后续 daemon 能力。

## 工作区变化后的恢复

任务会保存原始工作区路径。恢复时可能出现：

| 提示 | 处理方式 |
| --- | --- |
| 项目路径不存在 | 恢复目录到原路径，或取消任务 |
| 项目需要重新信任 | 从 Task Center 打开项目并确认信任 |
| Runtime 暂不可用 | 检查模型、配置、MCP 和项目状态 |

不要在任务暂停期间大规模切换分支或覆盖工作区，然后直接恢复写入任务。若确实发生变化，应先查看 Diff、Git 状态和 Checkpoint。

## 多任务并发建议

- 默认并发为 1，先确认单任务流程稳定再提高。
- 把互不依赖的工作拆成独立后台任务。
- 高风险写入任务不建议同时操作同一个工作区。
- 一个任务等待审批时，可以让只读任务继续。
- 多 Agent Worker 会额外占用模型与 Tool 预算。
- 同时运行多个高上下文任务可能触发 Provider 限流。

即使 Scheduler 允许并发，当前版本也没有为多个写入根任务提供独立 worktree 隔离。Git Checkpoint 可以恢复，但不能避免两个任务互相覆盖。

## 数据与审计

任务数据默认保存在：

```text
~/.deki/tasks/tasks.db
```

模型会话保存在：

```text
~/.deki/sessions/<workspace-hash>/
```

Tool 审计保存在：

```text
~/.deki/logs/audit-YYYY-MM-DD.jsonl
```

Task、Run、Plan、Worker Result 和 Artifact 使用 SQLite 持久化；Pi 会话仍使用 JSONL。二者通过 Session ID、Task ID 和 Run ID 关联。

## 常见问题

### 为什么后台任务一直排队？

常见原因是 `maxConcurrentRuns` 已满。也可能有另一个任务正在等待 Worker 或 Tool 完成。可以在 Task Center 查看运行中的任务，或谨慎提高并发上限。

### 为什么在后台按钮上点击没有反应？

确认：

- Prompt 不是空的。
- 模型 Runtime 已就绪。
- 输入内容不是 `/remember` 等会话命令。
- 项目任务已经信任工作区。

### 关闭窗口后任务是否继续？

取决于“关闭行为”设置。只有 Electron 主进程仍运行时才继续；明确退出应用一定会中断。

### 恢复会不会重复修改文件？

Deki 会提示 Agent 检查已有状态，不盲目重放已持久化 Worker 派发；但任意外部副作用都不能保证自动推断。恢复前仍应由用户检查工作区、Diff 和审计。

### 后台任务可以创建 Worker 吗？

可以。后台是交付方式，多 Agent 是任务内部执行方式。使用方法见[多 Agent 使用指南](./multi-agent-usage.md)。
